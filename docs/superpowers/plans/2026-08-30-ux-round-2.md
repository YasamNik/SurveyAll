# UX Round 2 — owner punch list (2026-08-30)

**Goal:** five owner-requested UX improvements on the live open demo.
**Spec context:** `2026-08-29-surveyall-design.md` (architecture rules unchanged),
`2026-08-30-surveyall-visual-design.md` (Paper Ballot tokens/components bind).
**Process:** subagent per task, task review each, prod redeploy + push at the end.

## Owner requests → tasks

### Task A — Editor + respond UX
1. **Rating config only for rating type:** min/max fields appear only when the
   question type select is `rating` (small client component for the type-dependent
   fields; server action contract unchanged).
2. **Stars everywhere for ratings:** respond page rating input becomes accessible
   stars (visually-hidden radios + SVG star labels, fill `--stamp` when selected,
   keyboard/AT intact, 44px targets); editor and results show ratings with star
   iconography. Star SVG inline, no icon library.
3. **Add question collapsed:** the add-question form hides behind an
   "Add question" button (`<details>`/`<summary>` styled as a secondary button —
   no JS). Open state after a validation error preserved (open the details when
   the error section targets add-question).
4. **Publish at the end + share box:** publish/close controls move to the bottom
   of the editor. After publish, show a share panel: full public URL in a
   read-only input + "Copy link" button (client component, `navigator.clipboard`
   with fallback select-text; "Copied" confirmation inline).

### Task B — Results as charts
Choice questions (single/multi) render as SVG donut charts (no chart library;
hand-rolled arcs), with a legend listing each option, its count and percentage —
zero-count options stay in the legend (honest zeros). Rating questions render the
star average plus a per-star count mini-chart. Free text stays a quoted list
(cannot be a pie). Colors follow the dataviz guidance distilled in the dispatch:
categorical palette derived from the Paper Ballot tokens, ≤6 distinct hues then
tints; every slice labeled via legend (never text inside thin slices); donut
center shows total responses for that question.

### Task C — Survey themes
- Schema: `surveys.theme text NOT NULL DEFAULT 'classic'` (drizzle migration).
- 8 themes: classic (paper), food, business, leisure, celebration, education,
  health, tech. Each = a subtle full-page background (inline-SVG pattern/wash as
  CSS data-URI — no photos, no external assets) + an accent override
  (`--stamp` swap) that keeps AA contrast. Paper Ballot structure unchanged.
- Editor: theme select (with the type-dependent-fields component or beside
  title/description form); PATCH accepts `theme` validated against the allowed
  list (Zod enum + server action guard).
- Public GET includes `theme`; respond + done pages apply the theme class.
- Results pages stay classic (charts carry the color).

## Constraints
- No API/domain contract changes beyond: `theme` column + field (additive), and
  none other. lib/domain purity and ESLint boundary hold. Length caps and rating
  bounds from the hardening commit stay intact.
- All CSS in `@layer components` (or theme classes at the same layer), tokens only.
- `corepack pnpm typecheck && lint && test && build` green per task; CI green at
  the end; prod redeploy + through-tunnel verification at the end.
